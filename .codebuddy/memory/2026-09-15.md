### 顺手修复的既有缺陷（notify 生成通知的 run 脚本）
bash 解析 `python3 -c '...'` 时，**python 代码块内出现单引号会提前终止 bash 字符串** → 整段 python 不执行、
`notice.md`/`notice.html` 不生成 → notify step 必失败。命中两处：
1. `'<html><body style="font-family:...sans-serif;' 'font-size:...">\n'`（拼 HTML）
2. `r'<a href="\2">\1</a>'`（Markdown 链接转 HTML）

修法：改用双引号 + 转义 —— `"<html>...\"..."`、`"<a href=\"\\2\">\\1</a>"`。
⚠️ **不能**图省事写成 r-string（`r"...\"..."` 会把反斜杠原样保留，HTML 里多出 `\`）。

### JoyCode 自动探测方案落地（用户提供真实下载地址后）
- 用户给出官方直链：
  `https://aichat.s3-ipv6.cn-north-1.jdcloud-oss.com/joycoder-ide/init/win32-x64/3.0.10/JoyCodeSetup.exe`
  实测匿名可下（HTTP 200 / 169992792 字节 / last-modified 2026-08-06），与本机已有 exe 同一文件。
- **关键规律：下载地址按版本号拼接** —— `<bucket>/joycoder-ide/init/win32-x64/<版本>/JoyCodeSetup.exe`
  - 该桶 `aichat` **禁止 ListObjects（403）**，但**允许匿名 GET/HEAD 具体对象**，不存在的版本返回 **404**；
  - 因此可用「候选版本号 HEAD 枚举」自动发现新版本并拼出下载地址，**完全不需要登录凭据**（比 Cookie 方案稳）。
- `check-joycode.sh` 改为三条路径（按优先级）：
  1. 手动 `JOYCODE_EXE_URL`（workflow_dispatch）
  2. **枚举（默认）**：URL 模板优先从记录 URL 推导（`${CUR_URL//$CUR_VER/{V}}`），否则用内置默认模板，
     也可用 `JOYCODE_URL_TPL` 覆盖；候选 = 当前 minor 的 patch+1..+30（`JOYCODE_SCAN_PATCH`）
     + minor+1..+5 × patch 0..2（`JOYCODE_SCAN_MINOR`）+ major+1..+2（`JOYCODE_SCAN_MAJOR`）；
     取命中集合的最大版本，按模板拼出 URL
  3. 官方接口（可选 `JOYCODE_COOKIE`，接口返回版本但无地址时也会用模板补）
- 实测：基线 3.0.10 → 47 候选、命中 0、判定无更新、约 15 秒；伪造基线 3.0.9 → 命中 3.0.10，
  自动得出 tag `joycode-v3.0.10-1` 与下载地址 ✅
- `latest-joycode-exe.txt` 已填入真实直链；文档/workflow 注释同步（不再宣称"必须配 Cookie"）。

- **发现并修复严重既有 bug（update-index 覆盖整份索引）**：
  - 根因：`update-index` 的 run 脚本引用 `$EXISTING`，但该变量**从未被赋值** → BODY 直接取 APPEND

  - 本地用真 token 演练修复后的脚本：输出「已取到现有索引：11 条下载链接」+「已包含本次资产，跳过写入」，`rc=0` ✅
- 教训：这类"读-改-写"步骤必须显式取回现有内容并在日志回显数量，防止静默覆盖历史数据。
