- **tag 用 `nopatch-v5.6.0-2`（刻意不以 `v` 开头）**：`build-deb.yml` 的触发条件是
  `on.push.tags: ['v*', 'joycode-v*']` —— 若用 `v5.6.0-2` 会触发 CI 构建**打补丁版**，
  而 CI 产出文件名正是 `com.xydw.workbuddy_5.6.0-2_amd64.deb`（**同名**），会把原味包覆盖掉。

- `github-release-pkg.txt` 已追加：`# 2026-09-20 10:37 WorkBuddy CN 5.6.0-2 原味版（不打 UI 补丁，仅观感差异）(amd64)`
- 坑：`gh release create` 只在 **GitHub 侧**创建 tag → 推 gitee 时先 `git fetch github --tags` 取回本地再推。

## 2. CI 改为 WorkBuddy 每版出双包（commit `eb6fb25`）

- `build` job 拆为：构建补丁版 → `mv` 到 `/tmp/deb-patched/` 暂存 → `--no-patch` 构建原味版 →
  重命名为 `<包名>_<版本>-nopatch_<架构>.deb` → 与补丁版一起上传（glob 仍为
  `src/com.xydw.workbuddy_*_<debarch>.deb`）。
- 两次构建按 `deb-pkg/DEBIAN/control` 自动错开 revision：实测 **5.6.0-2（补丁）/ 5.6.0-3（原味）**。
- `update-index` 无需改动 —— 资产名仍符合 `包名_版本_架构.deb` 解析规则（`-nopatch` 后缀不含下划线），
  会自动各收录一条，说明形如 `WorkBuddy CN 5.6.0-3-nopatch (amd64)`。
- **验证**：`gh workflow run build-deb.yml --ref master`（手动触发只跑 build job：`build-joycode`/
  `update-index`/`notify` 因 `if: startsWith(github.ref, 'refs/tags/')` 全部 skip → 只构建不发布）
  → run `35484664219` **全绿**：
  - x64：`com.xydw.workbuddy_5.6.0-2_amd64.deb`（148M）+ `com.xydw.workbuddy_5.6.0-3-nopatch_amd64.deb`（148M）
  - arm64：`com.xydw.workbuddy_5.6.0-2_arm64.deb`（147M）+ `..._5.6.0-3-nopatch_arm64.deb`
  - 耗时约 3.5 分钟/架构（原来 2.5 分钟，构建两次）
- 提交 `eb6fb25` 已推 `github` + `origin`(gitee) 两远程；下次真实发版（tag `v*`）会自动出 **4 个资产**。
